# PlayJigsaw 视觉解题器 · Part 3 混合 5×5

自动完成官方考核站 **<https://puzzle.moyunliuyin.me/?mode=exam>** 的
**Part 3（照片 + 纯白混合）· 5×5**：
25 个格子 + 5 块混淆碎片（共 30 块），全程只用**画面像素 + 真鼠标拖拽**，
不读取网页内部状态、不使用 Hint / Ghost / 自定义图片。

> 考核要求见 `docs/ASSESSMENT.md`：Part 3 需要 YOLO + OpenCV 联合，
> 5×5 难度必过；初始重叠 / 初始居中属于附加题（本版本未实现）。

## 二、快速开始

```bash
# 1) 环境（Python 3.10+；ultralytics 需要 3.10/3.11）
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 2) 跑一局 Part 3 · 5×5（默认加载自训练模型）
.venv/bin/python play_p3.py --difficulty 25 --headed

# 只看识别与指派、不拖拽
.venv/bin/python play_p3.py --difficulty 25 --dry-run

# 同一个浏览器里连跑 5 局（第二局起用"再来一局"，省掉重新加载）
.venv/bin/python play_p3.py --difficulty 25 --games 5

# 录演示视频（需要 playwright 自带 ffmpeg：playwright install ffmpeg）
.venv/bin/python play_p3.py --difficulty 25 --record demo_webm
```

> 浏览器用 `channel="chrome"` 复用本机 Chrome，不需要另外下载 Chromium。
> 本机网络若需要代理，`src/net.py` 会自动在"直连 / 127.0.0.1:1082"之间择优。

## 三、它怎么工作

```
                    ┌──────────────────────────────────────────────┐
  开题               │ 等初始 animals 渲染安静 → 开 Part 3 · 5×5       │
                    │ 校验预览里恰好 5 个纯白格（否则整页重开）        │
                    └──────────────────────┬───────────────────────┘
                                           ▼
  感知              30 块碎片（槽位锚定，整局只截一帧）      25 格参考图（原生 1600×1200）
                    ├─ alpha 覆盖率 → 有没有碎片             ├─ 纯白格：中心区 mean≈255、std<1.5
                    ├─ alpha 掩码   → 是不是纯白碎片          └─ 照片格：保留原图
                    └─ 卡扣密度     → 四边 凸/凹/直
                                           ▼
  定位              照片碎片 × 照片格：同视野中心区 Lab 三通道 NCC
                    + YOLO 类别先验（同类 +0.10 / top3 +0.04 / top5 外 −0.06）
                                           ▼
  指派              匈牙利算法求"总分最大"的 20 对；剩下的 5 块 = 混淆块
                    纯白碎片 × 纯白格：5! = 120 种排列穷举，用已知邻边互补打分
                                           ▼
  执行              环形顺序（外圈 → 内圈，满足锚点规则），逐格拖拽
                    ├─ 吸附成功 → 该格钉死，碎片出池
                    ├─ 没吸上  → 拖回原位 + 画面校验它到底在哪
                    └─ 还有空格 → 把"混淆块"放回候选兜底
```

### 1. 为什么 Part 3 可以"逐格比对"

读官方站源码（build `20261115r`）后确认，三部分的参考图**不是一回事**：

| 部分 | 参考图来源 | 能否像素比对 |
|---|---|---|
| Part 1 `renderAnimalGrid()` | `alternatePhoto()`：同类别的**另一张照片** | ❌ 只能认类别 |
| Part 2 `renderWhitePuzzle()` | 纯白画布 | — |
| **Part 3 `renderMixedPuzzle()`** | **`sourceCanvas.toDataURL()`：就是拼图源图本身** | ✅ 同一像素来源 |

碎片正是从这张源图上切下来的，所以"碎片中心 62%"和"它那一格的中心 62%"
几乎逐像素一致 —— 这是本方案定位精度的来源。YOLO 在这里的作用是**类别约束**：
同一类别可能对应多个格子（比如两格都是狗），NCC 负责在同类别候选里挑出唯一那一格。

### 2. 三个必须知道的规则（都来自官方源码）

1. **锚点**：`hasAnchor()` —— 外圈格子永远可放，内部格子必须已有邻居 `isPlaced`。
   所以拖拽顺序必须**外圈 → 内圈**，`ring_order()` 就是为此写的。
2. **吸附半径** = `max(0.14 × 碎片宽, 10px)`（5×5 实测 13.6px），比旧版紧一半。
   槽位锚定的位置误差实测 2.7–3.2px，刚好在半径内。
3. **混淆块**没有 `SOLUTIONS` 条目，**永远吸不上**。所以它们不能留在候选池里，
   否则每格都会被它们试一遍（实测能把一局从 25 次拖拽抬到 80+ 次）。

### 3. 开题时序（最容易翻车的地方）

页面加载时会先 `loadTheme('animals')`（默认主题，异步下载图片）；它加载完会
重绘 `sourceCanvas` 并 `startNewGame()`。如果我们已经开了别的题，就会被它覆盖成
照片题、计时器归零。现场表现就是"拼到一半题目变了"。

修法：`settle()` —— 等参考图 `src` **连续 2 秒不变**再点开始；开题后再等
"画布尺寸稳定 + 内容非空"才取图。Part 2 / Part 3 共用这一套。

### 4. 拖拽状态以画面为准

失败回拖这一下本身也可能抓空。所以每次失败后都用 alpha 覆盖检查
"原位有没有碎片"，没有就全画布重新定位这块碎片；定位不到才把它移出候选池。
把"拖拽失败"当成一次可恢复事件，而不是致命错误。

## 四、数据集与模型（自己采、自己标、自己训）

| 步骤 | 文件 | 说明 |
|---|---|---|
| 采数据 | `tools/collect_p3.py` | 每局保存 25 格参考图（原生 320×240）+ 30 块碎片核心区（灰底合成） |
| 自动标注 | `tools/label_p3.py` | 用官方题库 388 张原图逐张比对取 top-1；实测格子 20/20、碎片 20/20 |
| 组数据集 | `tools/build_p3_dataset.py` | **1011 张（909 训练 / 102 验证）**，按题库原图 + 分层划分，15 类都有验证样本 |
| 训练 | 见下 | `yolo11s-cls.pt` 微调 16 epoch（早停），MPS |
| 产物 | `models/p3cls_piece/weights/best.pt` | 15 类，11MB |

```bash
# 重新训练（可选）
.venv/bin/yolo classify train data=datasets/p3cls model=yolo11s-cls.pt \
    epochs=40 imgsz=224 batch=32 device=mps patience=12
```

训练集不包含"纯白"类：纯白碎片由 OpenCV 的 alpha/亮度判据处理，不交给 YOLO。

### 检测模型（交付用，和主流程分开）

除了分类模型，仓库还带两套 YOLO 检测模型（详见 [`docs/DETECT.md`](docs/DETECT.md)）：

| 模型 | 任务 | 数据 | 权重 |
|---|---|---|---|
| `p3det_obj` | 输入碎片/格子，检测主体（框+15 类） | 909 / 102（弱框），mAP50 **0.880** | `models/p3det_obj/weights/best.pt` |
| `p3det_piece` | 输入整张画布，检测 30 块碎片（1 类） | 85 / 25（槽位框+切块增强），mAP50 **0.994** | `models/p3det_piece/weights/best.pt` |

- `p3det_obj` 的框是**自动弱标注**（背景分割 + 中心兜底），类别来自题库自动打标；
- `p3det_piece` 的框来自**槽位公式**，是精确框；
- 两套检测模型**不参与** `play_p3.py` 主流程，用于 Part 1 风格的目标检测与画布定位演示。
`datasets/catalog/`（388 张原图）体积较大且属于第三方素材，仓库默认不包含，
可用 `tools/fetch_catalog.py` 重新拉取。

## 六、合规说明

考核规则（`docs/ASSESSMENT.md` §6.2）禁止的是：**读取/修改网页 JS 状态、读取正确坐标
或内部边缘矩阵、使用预存本局答案、按固定屏幕坐标硬编码**。本方案：

- 碎片与棋盘的位置全部来自**画面像素**（canvas 渲染结果 / 参考图 `<img>` 的显示内容）；
- 求解只用"边互补 + 直边 + 类别 + 像素相似度"，不碰 `SOLUTIONS` / `board.edges` / `window.app`；
- 参考图读取的是页面**展示给考生看的那张完成图**（Part 3 里就是源图本身），
  不是答案表；类别由自己训练的 YOLO 给出；
- 每次拖拽后都用画面校验状态，不依赖缓存坐标；
- `tools/` 里的采集/标注脚本只在**开发期**使用，不参与解题流程。

## 七、已知限制

- **初始重叠 / 初始居中**：未实现（附加题）。重叠开局没有等距槽位，需要先做轮廓分离。
- **Part 1（照片，参考图是另一张同类照片）**：未实现。它的定位只能靠"类别 + 试位"，
  与本方案的逐格比对是两条不同的技术路线。
- Part 2 能通关，但拖拽次数偏多（边标签精度还差一点），属于附带能力。
- 弱网下开题可能失败，程序会整页重开重试（最多 3 次）。
